### Item 4 -- Rithub self-serve provisioning + public landing page (apps/console)

Closes the backlog's named prerequisite chain: item 5 (OIDC, round 1) made
"one sign-in" true; this round builds the actual public discovery/signup
surface backlog item 4 asked for, so Rithub (live, zero-signup) stops being
wasted infrastructure.

- `apps/console/lib/gitea.ts` -- server-only Gitea admin API client.
  `provision({seed, email, repoName})` creates a dedicated Gitea **user**
  (`POST /admin/users`), then a private **org** and the first **repo**
  *as that user* via Gitea's documented `sudo=<username>` impersonation
  (`POST /orgs?sudo=`, `POST /orgs/:org/repos?sudo=`) -- so the org/repo end
  up correctly owned by the new account, not the admin token's own account.
  Username/org slugs follow switchyard-server's `signup.rs` pattern
  (lower-case alnum slug + random suffix, retried up to 5x on a 422
  collision).
- `apps/console/lib/config.ts` -- `gitea: {apiUrl, adminToken} | null` from
  `GITEA_API_URL`/`GITEA_ADMIN_TOKEN` (added to `SECRET_ENV`); `apps/console/lib/deps.ts`
  wires it, null until both are set (503, same gating pattern as Mint/OIDC).
- `apps/console/db/migrations/0014_org_gitea.sql` -- `orgs.gitea_username`,
  `gitea_org_slug`, `gitea_repo_url` (nullable).
- `apps/console/lib/types.ts`, `lib/repo.ts` (+`MemoryRepo`), `lib/postgrest-repo.ts`
  -- `Repo.setOrgGitea`.
- `apps/console/app/api/v1/rithub/provision/route.ts` -- `POST`, session-authed,
  same-origin-checked; idempotent at the route level (an org with
  `gitea_repo_url` already set returns the cached result and never calls
  Gitea again -- the client itself always creates a fresh account, so this
  check is what actually prevents a second account per org).
- `apps/console/app/rithub/page.tsx` (public, outside `(app)`) -- pitch page
  (git hosting, issues/PRs, Actions CI, LFS, npm registry, wiki, live at
  git.ereboslab.com) with a "Create your repo" CTA: signed out, links to
  `/auth/start?src=rithub-landing` (same cross-sell bridge pattern as items 1/2);
  signed in, renders `components/RithubProvision.tsx` (client component,
  one button -> `POST /api/v1/rithub/provision` -> shows the clone command
  and a link to the real repo). `components/Icons.tsx` gained `GitRepoIcon`
  (glyph, no emoji, matching the existing icon set).
- `components/Nav.tsx`'s stale "no SSO integration yet" comment corrected
  (OIDC shipped in round 1) and pointed at `/rithub` as the no-account path.
