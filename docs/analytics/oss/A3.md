### Substitution: aws4fetch instead of `@aws-sdk/client-s3`

The plan names `@aws-sdk/client-s3` (Apache-2.0). A3 uses aws4fetch (MIT, 11 KB, one file) to sign plain `fetch` requests instead:
- the full client is about 3.3 MB unpacked plus its dependency tree, and would have to be added to A1's manifest;
- the service runs under a 192 MiB cap, and it only needs `PUT`, `GET` and `DELETE` of whole objects;
- the S3 fake in `test/a3/exports.test.ts` verifies every Signature V4 with its own independent code, so the signer is checked against the specification rather than against itself.

## Security notes

- Recordings: every typed value is masked twice, by the SDK wrapper's defaults and again at ingest before bytes are stored; the stored chunks are checked byte by byte in tests (unit and Chromium).
- Player and map links are signed for one resource of one project for at most 10 minutes; the pages allow only this service's scripts, send no referrer, and are framed only by `PA_CONSOLE_ORIGIN`.
- The map page loads the customer's page in a sandboxed frame with scripts off unless the viewer turns them on, so viewing a map does not count as a visit.
- Exports: https only, no credentials in URLs, private and reserved addresses refused when the request is sent, no redirects followed, 10 s timeout. A DNS answer can still change between the check and the connection; pinning the resolved address needs an HTTP agent the service does not have, and is noted here as the remaining gap.
- Destination secrets are sealed at rest; a webhook's signing secret is shown once (a 5-minute, path-scoped, httpOnly cookie on the console side) and never read back.
