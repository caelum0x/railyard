Deliberate differences, each tested:
- The funnel window is measured from the first step (the vendored Umami SQL measured it from the previous step).
- A per-person event sequence number keeps one event from filling two steps.
- Funnel attempts that a later attempt always beats are pruned before the joins, and ties go to the latest attempt (upstream does not document its tie-break; counts are unchanged).
- Postgres picks regex greediness per expression, so the chain's text and link are extracted with `"([^"]*)"` instead of `"(.*?)"` (same stopping point).
- Weeks start on Monday.
- A missing breakdown value always keeps its own "(none)" line; the top-N limit applies to present values.

Test cases re-expressed from upstream behaviour as exact fixtures: `test/a2/funnels.test.ts` (several tries, window from the first step, strict, unordered, repeated step), `test/a2/grids.test.ts` (lifecycle four states on exact days, stickiness, day retention first time and recurring, paths with the 30-minute split, start and end points).
